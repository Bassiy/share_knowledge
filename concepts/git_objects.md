# Git 内部オブジェクトモデル

## 概要
Gitがローカルリポジトリに保存する4種類のオブジェクト（Blob・Tree・Commit・Tag）と、コンテンツをSHA-1ハッシュで管理するコンテンツアドレッシング方式の仕組み。

## 理解したこと

### 4つのオブジェクト

| オブジェクト | 保持する情報 | 特徴 |
|---|---|---|
| Blob | ファイルの中身のみ | ファイル名を持たない。1コンテンツにつき1オブジェクト |
| Tree | ディレクトリ構造。ファイル名 → BlobのSHA-1ハッシュの対応表 | サブディレクトリはTree内にTreeが入れ子（コンポジション構造） |
| Commit | 「いつ・誰が・なぜ」＋ルートTreeへの参照＋親コミットへの矢印 | 子コミットへの参照は持たない |
| Tag | 特定のコミットへの「目印（バージョン名など）」 | — |

```
Tree
├── "README.md" → <BlobのSHA-1>     ← ファイル名はTreeが持つ
├── "src/"      → <TreeのSHA-1>     ← サブディレクトリは別のTree
│    └── "main.py" → <BlobのSHA-1>
```

4つのオブジェクトが組み合わさったコミット2つ分の全体像：

```
[Tag v1.0]
    │
    ↓
[Commit abc123] ──parent──→ [Commit def456]
    │ tree                       │ tree
    ↓                            ↓
[Tree ghi789]              [Tree jkl000]
 ├─ "README.md" ─→ [Blob aaa111] ←─ "README.md"  ← 使い回し
 └─ "src/" ──→ [Tree bbb222]
                └─ "main.py" ─→ [Blob ccc333]
```

---

### コンテンツアドレッシング

コンテンツそのものをハッシュ化して、同一コンテンツは既存を使い回す。

GitのオブジェクトはSHA-1ハッシュがそのままファイル名になって `.git/objects/` に保存される。
中身が同じファイルはハッシュが同じになるため、ファイル名が違っても同じBlobを参照する。

```
file_a.txt（"Hello"） → SHA-1: abc123
file_b.txt（"Hello"） → SHA-1: abc123  ← 新規Blobは作られない
```

1バイトでも変わると別のSHA-1になるため、変更のたびに新しいBlobが生まれる。

---

### パックファイルと git gc

変更を繰り返すと `.git/objects/` のBlobが増え続ける。

`git gc`（ガベージコレクション）を実行すると、オブジェクトを**パックファイル**に圧縮する。

| 処理 | 内容 |
|---|---|
| 不要オブジェクトの回収 | どこからも参照されないオブジェクトを削除 |
| デルタ圧縮 | 似たオブジェクト同士の差分だけを保存（全コピーを持たない） |

Gitが自動で実行することもある。

---

### 内部構造から理解できる「なぜ」

| 現象・コマンド | 内部構造から見た理由 |
|---|---|
| `git reset` はコミットを「削除」しない | Commitオブジェクトは `.git/objects/` に残る。ブランチのポインタをずらすだけ |
| `rebase` でコミットIDが変わる | CommitオブジェクトはParent IDを含む。植え替えるとParent IDが変わる → ハッシュが変わる → 別のオブジェクトが生まれる |
| detached HEADのコミットが「消える」 | オブジェクト自体は残っているが、誰もそのIDを記憶していないため辿れなくなる |
| fast-forwardは「軽い」 | 新しいマージCommitオブジェクトを作る必要がなく、ブランチポインタを前進させるだけ |

---

### .git の2層構造：オブジェクトとリファレンス

`.git/` の中身は「不変の塊」と「可変のポインタ」の2層に分かれている。

| ディレクトリ | 管理方法 | 可変性 | 中身 |
|---|---|---|---|
| `.git/objects/` | ハッシュで管理 | 不変 | Blob・Tree・Commit・注釈付きTag |
| `.git/refs/` | 名前で管理 | 可変 | コミットハッシュへのポインタ |

```
.git/refs/
├── heads/main   → abc123（コミットのたびにハッシュ値を上書き ← ブランチ）
└── tags/v1.0    → def456（一度書いたら動かさない ← 軽量タグ）
```

ブランチの「軽さ」の正体はここにある。

ブランチの実体は `.git/refs/heads/` 以下のテキストファイル1つで、中身はコミットハッシュ1行だけ。
コミットするたびにそのファイルの中身を新しいハッシュで上書きするだけ。

軽量タグとブランチは同じ「コミットハッシュへのポインタ」だが、**動くかどうか**だけが違う。
