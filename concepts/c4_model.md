# C4モデル

## 概要
システムのアーキテクチャをContext・Container・Component・Codeの4階層で段階的にズームインして描く設計思想。

## 理解したこと

### 4階層の構造

「何を描くか」の思想であって、記法（UMLやMermaid）とは別軸の話。
各階層が「読者」と「粒度」を決めている。

| 階層 | 読者 | 内容 |
|---|---|---|
| Context | 非エンジニアも含む全員 | 外の世界との境界。システムが何と連携するか |
| Container | 開発チーム | システム内部の実行単位（アプリ・DB・Queueなど） |
| Component | 担当エンジニア | コンテナの内部構造 |
| Code | 個別開発者 | クラス・関数レベル。ほぼ省略される |

実際に管理するのはContext・Container・Deployment図が現実的。

---

### 特徴と活用

| 特徴 | 内容 |
|---|---|
| テキスト管理 | PlantUML・MermaidなどでGit管理・PRレビューが可能 |
| AIとの相性 | LLMへのインプット/アウトプットになれる「人間とLLMの共通言語」 |
| ADRとの組み合わせ | C4単体では「現状構造」のみ → 意思決定の記録はADRで補完 |

---

## 関連概念
- uml（C4モデルの記法として使えるUML）
- adr（C4で表現できない意思決定を記録する補完的手法）
