# DBインデックス

## 概要
検索を高速化するためにテーブルとは別に作成する物理的な参照構造。増やすほど読み込みは速くなるが、書き込みコストとストレージ使用量が増大するトレードオフがある。

## 理解したこと

### インデックスとは

「辞書」に相当する別途作成する参照データ。テーブル本体とは独立した物理領域に存在し、検索時にフルスキャンせずに目的のデータへ辿り着けるようにする。

### トレードオフ

| 観点 | インデックスが少ない | インデックスが多い |
|---|---|---|
| 読み込み速度 | 遅い（フルスキャン） | 速い |
| 書き込み速度 | 速い | 遅い（全インデックスを更新） |
| ストレージ | 少ない | 多い |
| 移行コスト | 低い | 高い（再構築コスト増大） |

### 書き込みが遅くなる理由

INSERT / UPDATE / DELETE のたびに、存在する全インデックスを更新しなければならない。インデックスの数だけ書き込みコストが線形に増える。

### ファイル名の命名理由

「インデックス」はDB以外にも存在するため（転置インデックス・配列インデックス等）、DB固有の概念であることを明示するため `db_index` と命名。

## 関連概念
- dbms（インデックスはDBMSが提供する高速検索機能の実体）
- normalization（正規化でテーブルを分割するとインデックス設計も変わる）
