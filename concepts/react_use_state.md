# React useState

## 概要
コンポーネントに状態（state）を持たせ、値が変わるたびに再レンダリングをトリガーするフック。

## 理解したこと

### 返り値は配列。名前が自由なのは配列の分割代入だから

| 分割代入の種類 | 例 | 名前の自由度 |
|---|---|---|
| オブジェクト分割代入 | `const { useState } = React` | プロパティ名で固定、変更不可 |
| 配列分割代入 | `const [count, setCount] = useState(0)` | 位置で取り出すため自由に命名可 |

```js
const [count, setCount] = useState(0);
const [seconds, setSeconds] = useState(0);
```

---

### 初期値が使われるのは最初のレンダリングだけ

| レンダリング | 使われる値 |
|---|---|
| 初回 | `useState(0)`の`0`（初期値） |
| 2回目以降 | Reactが内部で保持している現在のstate値（初期値には戻らない） |

明示的にリセットしたい場合は`setCount(0)`を呼ぶ必要がある。

---

### 値渡し vs 関数型の更新

| | 書き方 | Reactに渡すもの |
|---|---|---|
| 値渡し | `setCount(count + 1)` | その場で計算した確定値 |
| 関数型 | `setCount((prev) => prev + 1)` | 計算方法（レシピ）。実行時点の最新値で計算される |

計算タイミングと適用タイミングがズレると、値渡しは古い値をもとにした結果になる。

---

### バッチングでハマるケース
同じイベントハンドラ内で`setState`を連続呼びすると、Reactはまとめて処理する（バッチング）。

```js
// 値渡し：2回呼んでも+1にしかならない（両方とも同じ「その時点のcount」しか見ない）
setCount(count + 1);
setCount(count + 1);

// 関数型：都度最新値を引き継いで+2になる
setCount((prev) => prev + 1);
setCount((prev) => prev + 1);
```

`useEffect`内の古いタイミングで作られたコールバックがstateを更新する場合は、関数型の更新が必須になる（closure参照）。

## 関連概念
- react_props（更新用関数がpropsとして子コンポーネントに渡される流れ）
- closure（値渡しが罠になる根本原因＝古いタイミングで作られた関数が古い値を覚え続ける仕組み）
- react_use_ref（stateが再レンダリングをまたいで保持される仕組み＝コンポーネントのインスタンス側で値が保持されている点の詳細）
- javascript_promise（コールバック引数・分割代入の名前が自由な理由は「位置渡し」という共通の原則）
